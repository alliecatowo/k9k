# K9k core protocol v1

`K9k.app` starts `Contents/Resources/k9k-core` as its child process. The app communicates on stdin/stdout with one UTF-8 JSON object per line. Stderr is reserved for diagnostics and never parsed as protocol data.

Every request and envelope has `version: 1`. Requests contain a caller-generated `id`, operation name, optional `streamID`, and structured parameters. Responses echo `id`; asynchronous events echo `streamID`. Errors use a stable `code`, human-readable `message`, and optional structured details.

Implemented v1 operations are `health.ping`, `config.summary`, `config.document`, `config.write`, `context.list`, `context.select`, `namespace.list`, `discovery.list`, `resource.list`, `resource.get`, `relationships.get`, `manifest.get`, `manifest.apply`, `resource.watch`, `stream.cancel`, `resource.patch`, `resource.scale`, `resource.delete`, `resource.events`, `metrics.list`, `node.drain`, `logs.open`, `exec.open`, `exec.stdin`, `exec.resize`, `portforward.open`, and `rbac.check`. Generic resource operations carry group/version/resource plus explicit scope, namespace, name, selector, and raw Kubernetes object information. Watches emit incremental `resource.added`, `resource.modified`, `resource.deleted`, and `resource.watch.closed` events.

`relationships.get` takes the same resource identity as `resource.get` and returns one bounded read-only graph: its focal `rootID`, normalized nodes, directed owner/owns/selects/routes/uses edges, and non-fatal partial-snapshot warnings. It follows direct owner references and scans common workload/routing resources in the focal namespace; it never lists arbitrary CRDs cluster-wide.

`config.summary` is a read-only K9s compatibility operation. Its optional `directory` parameter selects a K9s configuration directory; without it the helper resolves `K9S_CONFIG_DIR`, then `XDG_CONFIG_HOME/k9s`, then `~/.config/k9s`. Its response contains sorted `aliases`, `hotkeys`, `plugins`, and `views`, plus a `files` map with each expected YAML file's path, presence, and parse/read diagnostic. Missing optional files are successful empty configuration, while an invalid file does not prevent valid sibling files from being returned. The operation only parses plugin declarations; it never executes plugin commands.

`rbac.check` is a non-mutating Kubernetes `SelfSubjectAccessReview` for the active kubeconfig identity. Parameters require `verb` and `resource`; `group`, `version` (default `v1`), `subresource`, `namespace`, and `name` are optional. A `gvr` string (`v1/pods` or `apps/v1/deployments`) is accepted in place of group/version/resource. The response is `{ "allowed", "denied", "reason", "evaluationError" }`. It cannot inspect arbitrary users, groups, or service accounts, and a denied response is a result rather than a protocol error.

`manifest.get` is the safe read endpoint for the native YAML editor. It accepts the normal named resource parameters (`gvr` or group/version/resource, `namespaced`, `namespace`, and `name`) and returns `{ "identity", "yaml" }`. `yaml` is canonical YAML for the selected object with `status` and API-server-managed metadata (`uid`, resourceVersion, managedFields, timestamps, and generation) removed. `identity` includes the immutable group/version/resource/scope/name/kind plus the selected object UID.

`manifest.apply` only updates an existing object that was previously selected. It requires that same resource identity, `expectedUID`, `kind`, and `manifest` YAML; its YAML must preserve apiVersion, kind, name, and namespace and must omit status and server-managed metadata. K9k always performs a direct server-side-apply dry run first (field manager `k9k`, never force). With `confirm: false` it returns `{ "validated": true, "applied": false, "manifest" }` without mutation. With `confirm: true` it validates first, then performs the same server-side apply for real and returns `applied: true`. Before each phase the helper fetches the object and verifies the UID, so a deleted/recreated object cannot be modified by a stale editor. SSA ownership conflicts return `manifest_conflict`; stale identity returns `identity_mismatch`; admission/schema failures return `manifest_validation_failed`. No `kubectl` process is involved.

`metrics.list` reads Kubernetes' optional `metrics.k8s.io/v1beta1` API directly through client-go—never through `kubectl top`. Parameters require `resource` (`pods` or `nodes`); `version` defaults to and currently only accepts `v1beta1`. For `pods`, `namespace` is optional (empty means all namespaces) and `name` optionally narrows the result to one pod. For `nodes`, `namespace` is invalid and `name` optionally narrows to one node. A successful response is `{ "apiVersion": "metrics.k8s.io/v1beta1", "resource", "items" }`. Each item has `apiVersion`, `resource`, `name`, optional `namespace`, RFC 3339 `timestamp`, sample `window`, canonical Kubernetes-string `usage` quantities, and `containers`; pod usage is the aggregate of its container usage while `containers` is empty for nodes. When Metrics Server or its APIService is not installed/available, the helper responds with `metrics_unavailable`, rather than emitting zero or stale utilization. Authorization and other API failures remain `kubernetes_error`.

`node.drain` requires `{node, ignoreDaemonSets:true, confirm:true}` and accepts `deleteEmptyDirData` only as a deliberate opt-in. It requires the node to have already been cordoned, lists its scheduled Pods directly, leaves mirror and DaemonSet Pods in place, blocks emptyDir Pods until opted in, and requests `policy/v1` evictions for every eligible Pod. It never force deletes; PodDisruptionBudget, grace-period, and RBAC failures are returned per-Pod in `{evicted, skipped, blocked, failures}`.

`portforward.open` creates one cancellable, direct client-go SPDY tunnel to a pod. It requires `streamID`, `namespace`, `pod`, and `remotePort` (1–65535); `localPort` defaults to `0`, which asks the OS to choose an available port. `localAddress` defaults to `127.0.0.1`; it may only be a loopback IP, so a forward is never exposed to the LAN. The success response is delayed until the tunnel and listener are ready and returns `{ "streamID", "status": "ready", "namespace", "pod", "localAddress", "localPort", "remotePort" }`, with the actual selected local port. The stream also emits `portforward.ready`, then exactly one `portforward.closed` (`completed`, `cancelled`, or `error`); unexpected post-ready failures additionally emit `portforward.error`. Use the existing `stream.cancel` operation with the same stream ID to stop the listener and API-server connection.

`exec.open` starts a direct client-go `pods/exec` SPDY stream for an existing pod. It requires `streamID`, `namespace`, `pod`, and a nonempty `command` argv array; optional `container` selects a container. The command is sent as Kubernetes argv, never interpolated into a local shell or `kubectl` subprocess. `tty` defaults to `true`, as does `stdin` for TTY sessions; non-TTY sessions default `stdin` to false. TTY sessions accept optional `initialColumns`/`initialRows` (default `80`×`24`). The initial response and `exec.started` event report the resolved request metadata. The helper emits zero or more `exec.stdout` and `exec.stderr` byte chunks as `{ "encoding": "base64", "dataBase64": "…" }`; decode and append them directly to a terminal emulator. Kubernetes combines stderr into stdout when `tty: true`, so no stderr chunks are expected in that mode. Exactly one `exec.closed` event follows with `reason` (`completed`, `cancelled`, or `error`), successful commands include `exitCode: 0`, and failed remote commands also emit `exec.error` with the Kubernetes exit code when available.

While an exec stream is active, `exec.stdin` accepts one ordered input frame. Put its `streamID` in either the request or parameters, then supply exactly one of UTF-8 `data` or binary-safe `dataBase64`; frames are capped at 64 KiB and the bounded queue reports `input_backpressure` instead of growing memory without limit. `exec.resize` accepts `streamID`, positive `columns`, and positive `rows`; it is valid only for a TTY stream and coalesces rapid resize events to the latest size. `stream.cancel` closes the Kubernetes connection, stdin, and resize queue. Missing/finished IDs return `stream_not_found` or `stream_closed` rather than accidentally writing to another session.

The helper owns client-go's kubeconfig merge/auth behavior and Kubernetes network I/O. Swift owns process supervision, request correlation, main-actor state, and presentation. Closing the app terminates the child; changing context or resource scope cancels the preceding watch.
