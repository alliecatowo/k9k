# K9k core protocol v1

`K9k.app` starts `Contents/Resources/k9k-core` as its child process. The app communicates on stdin/stdout with one UTF-8 JSON object per line. Stderr is reserved for diagnostics and never parsed as protocol data.

Every request and envelope has `version: 1`. Requests contain a caller-generated `id`, operation name, optional `streamID`, and structured parameters. Responses echo `id`; asynchronous events echo `streamID`. Errors use a stable `code`, human-readable `message`, and optional structured details.

Implemented v1 operations are `health.ping`, `config.summary`, `context.list`, `context.select`, `namespace.list`, `discovery.list`, `resource.list`, `resource.get`, `resource.watch`, `stream.cancel`, `resource.patch`, `resource.scale`, `resource.delete`, `resource.events`, `logs.open`, `portforward.open`, and `rbac.check`. Generic resource operations carry group/version/resource plus explicit scope, namespace, name, selector, and raw Kubernetes object information. Watches emit incremental `resource.added`, `resource.modified`, `resource.deleted`, and `resource.watch.closed` events.

`config.summary` is a read-only K9s compatibility operation. Its optional `directory` parameter selects a K9s configuration directory; without it the helper resolves `K9S_CONFIG_DIR`, then `XDG_CONFIG_HOME/k9s`, then `~/.config/k9s`. Its response contains sorted `aliases`, `hotkeys`, `plugins`, and `views`, plus a `files` map with each expected YAML file's path, presence, and parse/read diagnostic. Missing optional files are successful empty configuration, while an invalid file does not prevent valid sibling files from being returned. The operation only parses plugin declarations; it never executes plugin commands.

`rbac.check` is a non-mutating Kubernetes `SelfSubjectAccessReview` for the active kubeconfig identity. Parameters require `verb` and `resource`; `group`, `version` (default `v1`), `subresource`, `namespace`, and `name` are optional. A `gvr` string (`v1/pods` or `apps/v1/deployments`) is accepted in place of group/version/resource. The response is `{ "allowed", "denied", "reason", "evaluationError" }`. It cannot inspect arbitrary users, groups, or service accounts, and a denied response is a result rather than a protocol error.

`portforward.open` creates one cancellable, direct client-go SPDY tunnel to a pod. It requires `streamID`, `namespace`, `pod`, and `remotePort` (1–65535); `localPort` defaults to `0`, which asks the OS to choose an available port. `localAddress` defaults to `127.0.0.1`; it may only be a loopback IP, so a forward is never exposed to the LAN. The success response is delayed until the tunnel and listener are ready and returns `{ "streamID", "status": "ready", "namespace", "pod", "localAddress", "localPort", "remotePort" }`, with the actual selected local port. The stream also emits `portforward.ready`, then exactly one `portforward.closed` (`completed`, `cancelled`, or `error`); unexpected post-ready failures additionally emit `portforward.error`. Use the existing `stream.cancel` operation with the same stream ID to stop the listener and API-server connection.

The helper owns client-go's kubeconfig merge/auth behavior and Kubernetes network I/O. Swift owns process supervision, request correlation, main-actor state, and presentation. Closing the app terminates the child; changing context or resource scope cancels the preceding watch.
